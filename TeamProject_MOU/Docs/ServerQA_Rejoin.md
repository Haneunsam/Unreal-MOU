# ServerQA: 게임 중 입장·재참여 검증

## 변경 동작

- 대기중·게임중·정원이 찬 방을 방 목록에 표시한다. 정원이 찬 방의 참여 버튼은 비활성화한다.
- 빈자리가 있으면 기존 참여 계정과 새 계정 모두 게임 중 입장할 수 있다. 비밀번호 검사는 유지한다.
- 메인로비 버튼은 방에서 퇴장한 뒤 MainLobby로 이동한다. 로그인 연결은 유지하며 WBP_LobbyWidget을 표시한다.
- 게임 종료 버튼은 서버 연결을 명시적으로 닫는다. 서버의 실제 연결 종료 처리가 멤버·계정 접속·릴레이 경로를 정리한다.
- 같은 계정으로 재실행·로그인한 후 방 목록에서 살아 있는 방을 선택해 다시 입장한다. 자동 재입장은 아니다.
- 호스트는 중도 입장 때 맵을 다시 열지 않는다. 현재 리슨 소켓에 새 참여자의 릴레이 경로를 등록하고, 서버는 준비 확인 후 해당 참여자에게만 출발 신호를 보낸다.
- 접속 준비마다 발급한 요청 번호로 이전 입장의 늦은 준비 응답을 차단한다.
- 참여자의 직접 연결·릴레이 연결이 최종 실패하면 방에서 나가고 MainLobby로 복귀하여 재시도할 수 있게 한다.
- 호스트가 종료하면 방은 삭제된다. 호스트 이양 및 이전 캐릭터의 위치·체력·인벤토리 복원은 이번 구현 범위가 아니다.

## 빌드 및 실행

이번 공유 프로토콜 버전은 **16**이다. 서버와 모든 게임 클라이언트를 같은 수정본으로 빌드해야 한다. 버전 15 실행 파일을 섞으면 로그인이 거부된다.

서버 PC에서는 ServerQA 변경을 받은 뒤 기존 `MOU_Server/build_server.bat`으로 다시 빌드하고 `MOU_Server/run_server.bat`으로 실행한다. 기존 계정을 사용하려면 기존 계정 DB 경로를 유지한다. 이 작업에서 운영 DB와 서버 설정은 변경하지 않았다.

게임 PC는 UE 5.8로 `TeamProject_MOUEditor Win64 Development`를 빌드하거나 동일 소스로 게임을 패키징한다. 에디터에서 테스트할 경우 각 프로세스가 별도로 로그인하도록 실행한다.

현재 서버 주소 확인은 게임 콘솔의 `MOU.Chat.Server`를 사용한다. PC별 주소 변경은 `MOU.Chat.SetServer <서버주소> 9000`을 사용할 수 있다.

기존 실행 스크립트의 기본 외부 접속 경로는 서버의 TCP/UDP 9000과 UDP 릴레이 10000–10127이다. 실행 로그에서 공인 주소와 릴레이 시작 여부를 확인한다. 직접 연결이 실패하면 릴레이로 전환하므로 외부 검증에는 해당 릴레이 경로가 필요하다.

## 로컬 자동 검증

CMake와 C++ 도구가 설정된 터미널에서 저장소 루트를 기준으로 실행한다.

```text
cmake -S MOU_Server -B MOU_Server/Server_Build/serverqa-tests
cmake --build MOU_Server/Server_Build/serverqa-tests --config Release
ctest --test-dir MOU_Server/Server_Build/serverqa-tests -C Release --output-on-failure
```

- RoomSlotsTest: 기존 대기실 좌석 배정.
- RoomCustomizationTest: 기존 외형 검증.
- SessionAuthTest / AccountAvailabilityTest: 계정 접속 소유권 및 계정 검사.
- RoomRejoinTest: 게임 중 목록·정원·비밀번호·새 계정 입장·동일 계정 재입장·오래된 승인 거부·방장 종료.
- RoomRejoinIntegrationTest: 메모리 계정 DB와 실제 서버 ClientThread, 루프백 TCP 및 UDP를 사용한다. 최초 시작, 중도 입장, 메인로비 퇴장, TCP 종료 후 동일 계정 로그인, 릴레이 양방향 전달·기존 경로 보존·실패 경로 해제를 검증한다. 운영 서버에 접속하지 않는다.

통합 테스트는 Unreal 게임 프로세스를 대신하는 프로토콜 클라이언트로 호스트 준비 응답을 보낸다. 따라서 자동 테스트 통과만으로 실제 WBP 표시, 게임 캐릭터 생성, 서로 다른 NAT 환경의 접속까지 검증한 것은 아니다.

## 다른 네트워크에서 수행할 최종 플레이 검증

1. 호스트 A와 다른 네트워크의 참여자 B가 로그인한다. A가 방을 만들고 B가 입장·준비한 뒤 게임을 시작한다.
2. 양쪽에서 서로의 캐릭터가 보이고 이동 상태가 동기화되는지 확인한다.
3. B가 인게임 메뉴의 메인로비 버튼을 누른다. A의 게임은 계속 실행되고, B에는 로그인 화면 없이 메인로비 UI가 표시되어야 한다.
4. B의 방 목록에 A의 방이 게임중으로 남아 있고 인원수가 감소했는지 확인한다. 다시 참여하면 A의 맵을 초기화하지 않고 B만 접속해야 한다.
5. B가 게임 종료 버튼으로 프로세스를 종료한다. 게임을 다시 실행하고 같은 아이디로 로그인한 뒤 동일 방에 다시 참여한다.
6. 새 계정 C도 빈자리가 있으면 게임중 방에 참여할 수 있는지 확인한다. 정원 초과 및 잘못된 비밀번호는 거부되어야 한다.
7. B가 나간 뒤 새 방을 만들거나 다른 대기중 방에 참여할 수 있는지 확인한다.
8. 호스트 A 종료 후 방 목록에서 해당 방이 사라지는지 확인한다.

실패 시 서버의 `[중도 입장]`, `[방 퇴장]`, `[종료]` 로그와 게임의 `[릴레이]`, `[접속 실패]`, `[이동 실패]` 로그를 함께 확인한다. 프로토콜 접속 성공과 실제 게임 연결 성공은 구분한다.

외부 PC의 배포 및 위 실기 검증은 사용자가 추후 수행할 예정이다. 아직 외부 네트워크 접속 완료로 판정하지 않는다.
