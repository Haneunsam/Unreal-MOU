# 터미널 상점 구현 작업 메모

## 목표

리썰 컴퍼니처럼 플레이어가 모니터에 상호작용해 명령어를 입력하고, 아이템을 주문하는 상점을 만든다. 첫 구현 범위는 `store`, `<상품명> <수량>`, `confirm`이다. 예: `potion 2`를 입력하면 주문 내용과 총액을 보여주고, `confirm`을 입력하면 구매한다. 취소 및 잘못된 명령에 대한 안내도 제공한다.

## 플레이 흐름

1. 플레이어가 모니터를 바라보고 상호작용하면 터미널 UI가 열린다.
2. `store`를 입력하면 구매 가능한 상품명과 가격이 표시된다.
3. `potion 2`처럼 입력하면 상품명·수량을 해석하고 총액을 계산해 확인 문구를 표시한다. 이 시점에는 골드를 차감하지 않는다.
4. `confirm`을 입력하면 서버가 상품, 수량, 가격, 보유 골드, 주문 가능 상태를 다시 검증한다.
5. 검증에 성공하면 팀 골드를 차감하고 지정된 수령 위치에 아이템을 생성한 뒤 완료 메시지를 표시한다.
6. UI를 닫으면 입력 포커스와 마우스 상태가 게임 조작으로 돌아온다.

```text
> store
potion      50 G
taser      200 G

> potion 2
포션 2개 주문: 100 G
구매하려면 confirm

> confirm
구매 완료! 수령 위치에 아이템이 생성되었습니다.
```

## 현재 프로젝트에서 재사용할 코드

- `TeamProject_MOU/Source/TeamProject_MOU/Public/Item/ItemSpawnRow.h`: `FItemSpawnRow`의 `ItemClass`, `ItemName`, `Price`를 상품 정보로 사용한다. 명령어용 이름은 표시 이름과 분리할지 검토한다. 우선 데이터 테이블의 행 이름을 명령어로 사용하면 파싱이 단순하다.
- `TeamProject_MOU/Source/TeamProject_MOU/Public/Item/ItemSpawner.h`: `SpawnItemAt`으로 서버에서 구매 아이템을 생성한다.
- `TeamProject_MOU/Source/TeamProject_MOU/Public/Base/ProjectGameStateBase.h`: `Gold`, `CanAfford`, `SpendGold`로 팀 골드를 확인하고 차감한다.
- `TeamProject_MOU/Source/TeamProject_MOU/Public/Item/ShopBase.h`: 기존 진열형 상점이다. `TryPurchaseItem`의 서버 결제 패턴은 참고하되, 터미널 주문은 진열 아이템을 구매하는 방식이 아니므로 별도 처리 흐름이 필요하다.
- `TeamProject_MOU/Source/TeamProject_MOU/Public/Components/InteractionComponent.h`: 플레이어가 바라보는 상호작용 대상을 감지한다. `PerformInteraction`은 로컬에서 실행된다.

## 구현 설계

- 모니터 액터에 상호작용 인터페이스와 터미널 UI를 연결한다. UI에는 출력 영역과 `EditableTextBox`를 둔다. 입력창의 Enter 이벤트에서 명령 문자열을 전달한다.
- `store`는 데이터 테이블에서 구매 가능한 행을 읽어 목록을 출력한다. 상품 입력은 공백을 정리한 뒤 마지막 토큰을 수량으로 해석하고, 나머지를 상품 키로 사용한다. 수량은 양수이고 상한을 둔다.
- 주문 대기 상태는 플레이어별로 유지한다. 다른 플레이어의 `confirm`이 내 주문을 결제하지 않도록 한다.
- 구매 요청은 클라이언트 UI가 서버로 보내고, 서버에서 실제 상품·가격을 다시 읽어 골드 차감과 스폰을 수행한다. 클라이언트가 보낸 가격은 신뢰하지 않는다. 골드 부족, 상품 없음, 잘못된 수량, 스폰 실패에 대한 결과를 UI에 보여준다.
- 첫 단계의 수령 방식은 모니터 옆 지정된 스폰 지점으로 한다. 이후 필요하면 배달 연출로 확장한다. 구매 확정과 생성 실패 시 환불 등 원자적인 처리 순서를 구현할 때 확인한다.
- UI 입력 중에는 캐릭터 이동·채팅 입력과 충돌하지 않게 입력 모드를 관리하고, 닫을 때 원래 상태로 복구한다.

## 작업 전 확인할 것

1. 실제 모니터를 배치할 맵과 메시 또는 기존 블루프린트를 확인한다.
2. 사용할 아이템 데이터 테이블과 명령어로 노출할 상품을 확인한다.
3. 모니터 옆 즉시 수령이 맞는지, 기존 창고/배달 흐름을 원하는지 결정한다.
4. UE 5.8 에디터 접근 여부를 확인한다. `.uasset`과 `.umap`은 텍스트 편집으로 수정하지 않는다.
5. 멀티플레이에서 호스트와 클라이언트 각각 주문·결제·수령을 검증한다.

## 저장소 수정 규칙

`AGENTS.md`에 따라 `Public/Item/`과 `Private/Item/` 밖의 스크립트는 **실제 수정 전에 사용자에게 관련 현재 코드와 제안 코드, 이유, 영향, Item 폴더 안의 대안을 제시하고 명시적 승인을 받아야 한다**. 상호작용 컴포넌트나 플레이어 컨트롤러에 서버 RPC를 추가해야 한다면 이 절차를 먼저 진행한다. 승인 전에는 해당 스크립트를 수정하지 않는다. 새 함수는 `.h` 선언과 `.cpp` 정의에 동일한 한국어 CodeName 주석을 단다.

## 현재 상태

첫 단계로 `ATerminalShop` 상호작용 액터와 `UTerminalShopWidget`을 Item 폴더에 추가하고, `/Game/04_JJO/TerminalShop/BP_TerminalShop`을 생성했다. 현재 UI는 정적 시안 대신 `/Game/04_JJO/TerminalShop/UI`의 개별 이미지와 폰트로 구성된다. 왼쪽에서 포션·테이저를 선택하면 오른쪽의 이미지·설명·가격이 바뀌고, 수량 ± 버튼과 주문 합계가 갱신된다. 팀 골드는 현재 GameState 값을 표시한다. 취소 또는 Esc로 닫을 수 있으며, 결제 버튼은 아직 실제 구매를 실행하지 않고 미연결 안내를 표시한다. UE 5.8 에디터 빌드와 BP·UI 에셋 로드 확인을 완료했다. 맵 배치 및 PIE 조작 검증은 아직 진행하지 않았고, 기존 맵 에셋의 사용자 변경은 보존한다.
